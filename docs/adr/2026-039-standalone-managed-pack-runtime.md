# 2026-039: Load managed packs from one verified runtime snapshot

**Status:** accepted for the standalone Claude Code runtime and public `bounded add` in issue #67. Amends [ADR 2026-034](2026-034-managed-pack-artifacts.md), [ADR 2026-035](2026-035-managed-pack-lock-verification.md) and [ADR 2026-038](2026-038-managed-pack-type-projection.md).

## Decision

`bounded add name@version` accepts an exact package version from an HTTPS npm-compatible registry. The executable verifies the installed Bounded release, the package and its pinned dependency graph, checks the complete proposed graph against the runtime size limits, then publishes the type-only editor projection and lock through the shared writer. It returns the requested package's verified catalogue imports from that writer-held transaction and prints them after success; it does not reread a later mutable lock for command output. It does not edit `bounded.config.ts` or select a pack. Project `node_modules` holds declarations, not pack JavaScript.

Before a Claude Code hook evaluates project configuration, Bounded checks the projection receipt, lock, complete store graph and installed release, then copies every verified package file into a bounded in-memory graph. Each copied file is checked against the locked inventory; graph size, file count and total bytes are bounded. The lock and receipt bytes are bound to the projection verification result. A final check that no journal is pending and that their digests are unchanged selects the snapshot for that hook. An add published after this point applies to the next hook: the current hook uses its original copied bytes or refuses. The hook does not hold the project writer while arbitrary project or pack code runs.

The project config builder resolves a direct bare import only through a lock root. An import made by a managed package resolves through that package's own pinned dependency edge, so two parents can load different versions of the same dependency. Package exports use the Node import-condition resolution checked at installation. Relative managed imports stay inside that package's copied files. Bounded's public subpaths bind to the executable's own frozen module objects, preserving nominal pack identity. The builder takes project source bytes from the project, rejects nonliteral dynamic imports and `require`, checks containment, and rechecks those source files before executing the generated bundle. The output directory is private to the process and removed on normal exit.

Only packs selected by the project and their transitive `dependsOn` objects enter composition. Before composition, the Claude Code config source compares each managed selected object's runtime descriptor with its locked catalogue fields: id, dependencies, contribution point ids, declared points, and required and optional ports. It also proves the object is the named export at the catalogue's import path in the evaluated module graph. Catalogue summaries, documentation, examples and schemas are author documentation rather than runtime pack fields and are not compared here. Bounded does not import an unreferenced installed pack for catalogue validation or composition. A project config's explicit import can execute a pack module even when the config does not select that pack for composition. Catalogue pack exports use ESM targets under ADR 2026-034. A selected pack with a required port still needs an explicit port provision; installation does not supply one automatically.

This is a consistency and workflow boundary, not a sandbox for project or package JavaScript. Evaluating selected modules gives them the process's normal permissions. The runtime never loads executable bytes from the editor projection or ambient `node_modules`. The compiled release bundles its TypeScript parser; the published Node package declares the same pinned parser dependency for its carried host code.

`bounded check`, project-supplied third-party port provisions, standalone pi hooks and native Windows killed-writer recovery remain separate work. The editor projection's Windows reclaim test is a release gate under ADR 2026-038.
