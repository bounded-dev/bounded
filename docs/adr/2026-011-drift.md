# 2026-011: Undoing what shell commands change in watched files

**Status:** accepted.

## Decision

- **A core extension point, `watchedPaths`**, on the core pack: files a shell
  command must not change (`match`, `except`, `why`, `redirect`), checked by
  `WatchedPath.parse`. Mechanism only: packs (the path gate, after its
  merge) and projects contribute the paths.
- **A new event, `ToolResult`**: a finished tool call (role, tool, effects,
  `ok`, `callId`), parsed like a tool use. `ToolUse` gains an optional
  `callId`, so a snapshot taken before a call can be found after it. It is
  not part of `Event`: guards judge calls before they run; results are
  checked for drift.
- **An application feature, `drift/watch-shell`**, with two operations,
  `snapshot` before an allowed call with an `execute` effect and `verify`
  after it, and two async out ports so the core names no technology:
  `WatchedFiles` (hash the watched files; restore paths from version
  control, removing files it never held) and `ShellSnapshots` (keep a
  snapshot per call id). The judge's new check before allowing runs the
  snapshot, so a failure refuses the command and the refusal is what is
  recorded.
- **File-backed snapshots.** Claude Code runs each hook as its own process,
  so snapshots live in `.bounded/snapshots/` (one file per call, named by a
  hash of its id, mode 0600); an in-memory store serves tests and
  single-process hosts.
- **Fail closed.** No call id, or hashing failing before the command, refuses
  it. After the command, a failure to hash or restore, or a restore that
  leaves a file different from the snapshot, is reported loudly to the agent
  and recorded.
- **File system adapter**: Bun's own glob to find files, node:crypto for
  SHA-256, git to restore (`git cat-file -e HEAD:<path>`, `git checkout HEAD
  -- <path>`), deleting files HEAD does not hold.
- **Hosts** call `judge(toolUse)` and `afterTool(toolResult)` on the
  `ProjectJudge` from `openProject`.

## Deviations from the example

The feature's in port has two methods (before and after a call), not one
`execute`; they share the snapshot. It reuses judge-event's `DecisionLog`,
`Clock` and `DecisionIds` ports.

## Consequences

A shell command's changes to watched files never survive it, but restoring
goes to the last commit, so uncommitted work in watched files is reported
rather than restored, and nothing stops a command reading protected files
while it runs.
