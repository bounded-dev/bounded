# 2026-016: One package, `bounded`, carrying the CLI and the host adapters, for Node

**Status:** accepted (the maintainer's decisions, in the reviews of issue
#65's first slice).

## Decision

- **Separate apps in source, one package on npm.** The CLI (`apps/cli`), the
  Claude Code adapter (`apps/claude-code`) and the pi adapter (`apps/pi`) stay
  separate private workspace apps under the app rules. The core's source
  never imports them, and no app imports another. At pack time, `bounded`'s
  `prepack` (`contexts/core/build-dist.ts`) builds them into `bounded`'s
  `dist/`, so one package is published and nothing else. Like TypeScript's
  `tsc`, users install one package and run `npx bounded init`. The adapters
  can be split into packages of their own in a later major version.
- **Nothing needs bun at run time.** The build compiles to JavaScript for
  Node:
  - the library entry points, in one code-split build mirroring `src/`, so
    code two entry points share (such as the path gate's port keys) stays one
    module;
  - the CLI (`dist/cli.js`, `bounded`'s bin);
  - the Claude Code hook (`dist/hosts/claude-code/hook.js`) and installer;
  - the pi extension (`bounded/hosts/pi`) and installer.

  Every package import stays external: `bounded/*` resolves through the
  package's own export paths, and the build refuses any other import that is
  not one of `bounded`'s dependencies. So tree-sitter's grammar and the rest
  load from `node_modules`.
- **Exports run from dist under Node, with the source beside them.** Each
  library export path has `default` (the `dist/` build), and `types` and
  `bun` (the TypeScript source, shipped too).
  - The installer conformance suite is a `bun:test` module, so it has only
    `types` and `bun`.
  - The host entry points (`./hosts/claude-code/host-installer`,
    `./hosts/pi`, `./hosts/pi/host-installer`) are `dist/` only.
  - `engines` is `node >=22.18`, the Node that strips TypeScript's types.
  - Bun is needed only to build and publish.
- **The Claude Code hook runs under Node**:
  `node "$CLAUDE_PROJECT_DIR/node_modules/bounded/dist/hosts/claude-code/hook.js"`.
  `isBoundedHook` replaces earlier forms: bun, the `bounded-claude-code`
  package, absolute paths.
- **`bounded.config.ts` loads under Node** whatever the project's `"type"`.
  `npm init -y` writes `"commonjs"`, so a load hook makes Node load the
  configuration as TypeScript ESM. A Node that cannot strip types fails
  closed, saying to upgrade or to use `bounded.config.js` or `.mjs`.
- **The CLI installs and upgrades `bounded` alone; the configuration is the
  CLI's.**
  - `bounded init [--host <host>]... [--from <dir>]` adds `bounded` at the
    CLI's own version, from the npm registry or from its tarball in `<dir>`.
    It then hands over to the installed `bounded init --no-install --host
    <host>...`, which writes the configuration and installs the hooks of the
    hosts named or found (`.claude/`, `.pi/`).
  - The configuration it writes (`apps/cli/src/initial-config.ts`) is live:
    the core, the path gate, and the path gate's two default rules
    ([ADR 2026-009](2026-009-path-gate-pack.md)). The core's init feature
    writes whatever text it is given, so the core holds no content.
  - `bounded update [--from <dir>]` upgrades `bounded` to its latest (or to
    the tarball), then hands over to the installed
    `bounded update --no-upgrade`. Other packages are left alone, including
    a third-party host adapter.
  - Those hand-offs are the contract between versions: every version accepts
    `bounded init --no-install [--host <host>]...` and
    `bounded update --no-upgrade`.
- **Host selection.** `bounded` offers one installer per host at
  `./hosts/<host>/host-installer`. The CLI runs those only for the hosts named
  or found; another package's `./host-installer` always runs
  ([ADR 2026-015](2026-015-host-installers.md)). The list of bundled hosts
  lives in the build script and the package manifest, never in the core's
  code.
- **Package managers.** The package manager is the lockfile's, else
  `package.json`'s `packageManager`, else the one running npx
  (`npm_config_user_agent`), else npm.
  - A registry upgrade uses its own add command with `bounded@latest`.
  - A tarball install writes the spec and that manager's override of
    `bounded` into `package.json`, then runs its plain install:
    - npm (`overrides`) and pnpm (`pnpm.overrides`) use `$bounded`; npm
      refuses an override that differs from the direct dependency
      (EOVERRIDE).
    - bun (`overrides`) and yarn (`resolutions`) use the tarball.
  - Any failure restores `package.json` and the lockfiles.

## Why

The core owns mechanism, never content. Package managers, npx, bundling and
the hosts' adapters are distribution's concerns. Keeping them in apps keeps
the core's rules, and bundling them into one package gives users one install
and one command. Compiling for Node lets a project with only Node and
npm, pnpm or yarn use Bounded. Most machines that run Claude Code have no bun.

## Consequences

- The core's pinned list of export paths in `architecture.test.ts` gains the
  three host entry points and `./testing/host-installer-conformance`.
  `architecture.test.ts` reads a conditional export's source (`bun`, else
  `types`) for its rules, and checks every condition's target exists. The
  tests' preload (`test-preload.ts`) builds `dist/` first.
- The workspace uses bun's hoisted linker (`bunfig.toml`). Bun mis-resolves a
  conditionally exported package reached through several workspace symlinks,
  which the isolated linker makes.
- While npm's `bounded` is the legacy 2.x
  ([ADR 2026-014](2026-014-legacy-harness-moves-to-legacy.md)), a tarball
  install overrides it, and npx is given the tarball:
  `npx -p <dir>/bounded-<v>.tgz bounded init --from <dir>`. Once 3.0.0 is
  published, `npx bounded init` is the first step.
- bun and npm are exercised end to end. One npm run has no bun on `PATH` and
  pipes Claude Code payloads through the installed hook. pnpm and yarn are
  unit-tested only.
