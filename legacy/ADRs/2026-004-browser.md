# 2026-004: Browser automation via betterwright

**Status:** accepted

## Decision

Adopt `npm:betterwright` (global) as the harness's browser capability: a
persistent, policy-guarded Playwright browser the agent can drive across
turns — navigation, input/gestures, in-page JS, screenshots.

## Why

- Recurring need beyond any one project: visual iteration on game/rendering
  work (Skimline) **and** credentialed web tasks like quarterly accounts.
  Persistent sessions avoid re-login cost; the vault + network policy +
  sandboxed model code are the features that make credentialed use
  acceptable.
- The runtime is the expensive part (session management, snapshot
  compression, sandboxing, proof screenshots) — same adopt-vs-build logic
  as pi-subagents (2026-003). A thin custom Playwright script was considered
  and rejected: it covers one-shot screenshots but not persistent
  credentialed sessions.
- pi-lens was evaluated in the same pass and **rejected**: its per-edit
  diagnostics value is already covered by the pi-subagents watchdog's
  changed-file LSP pass and by `tsc --noEmit` habits; the package is a
  20 MB kitchen sink.

## Consequences

- Global install — this is a cross-project capability, recorded in
  `settings.json` packages.
- Sensitive surface: credential vault, network egress, CAPTCHA helpers.
  Review source on update (`pi update --extensions`); keep vault usage
  deliberate, never let secrets enter transcripts.
- Project-scoped browser needs can still override with a project-local
  install/config.
