# Reference domain — copy the shape, not the content

This is the worked example's domain: one bounded context,
`contexts/project-management`, with two areas (`notes`, `projects`) and six
concepts in the contract-owns-the-name form (ADR 2026-059, TN-26-012). It
exists so an agent starting a build can read the shapes the gates enforce
instead of reconstructing them from prose. **Transfer the structure; do not
carry the domain across.** Your ticket is not about projects and notes.

It is **gate-verified in CI**: `packs/ts/scripts/reference-component.test.ts`
runs over it on every `npm run check`, so the example can never drift from the
rules it teaches (TN-26-008).

## What each file shows

Under `contexts/project-management/src/domain/`:

- **`notes/note-id.contract.ts`, `projects/project-id.contract.ts`** —
  identifiers: `interface <Name>` with `readonly __brand`, one
  `readonly value: string`, `equals`, `toJSON`, and `interface <Name>Factory`
  with `generate()` and `parse(raw: unknown): Result<Name>`.
- **`notes/note-text.contract.ts`, `projects/project-name.contract.ts`** —
  value objects: the same pair without `generate`, and a doc comment stating
  the validity rule with two `@accepts` examples, which the generated laws use
  as samples. `value-object-documented` requires them; the worked example
  itself carries no doc comments, so these two are the one addition.
- **`notes/note.contract.ts`, `projects/project.contract.ts`** — entities:
  identity first, value-object fields, a factory that is exactly
  `new (…fields): Name`, and a `toJSON` of one primitive per field. A note
  refers to its project by `ProjectId`, never by holding the `Project`.
- **`<concept>.ts`** — the implementations: an unexported `<Name>Impl
  implements Contract.<Name>`, `parse` over a zod schema (`zod-backed-parse`),
  and the two generated exports at the end (`impl-tail`).
- **`<concept>.laws.test.ts`** — generated by the domain emitter
  (`packs/ts/scripts/domain-emitter.ts`); never hand-edited. CI holds them to
  exactly what the emitter produces today.
- **`<concept>.test.ts`** — the test-writer's level: for value objects and
  identifiers, the wrong-value rejections no generator can know; for
  entities, the behaviour and wire shape.
- **`index.ts`, `shared/result.ts`** — the generated domain barrel and the one
  `Result` type (both ts-hexagonal's generated files).

## What CI checks

Every contract passes `contract-purity`; every implementation passes
`impl-tail` and `zod-backed-parse` and keeps the emitter's tail; the committed
laws equal the emitter's output. With `bun` on the machine, the context
typechecks under `bunx tsc`, its whole suite passes under `bun test`, and
against the emitted skeletons the same suite fails only with
`NotImplementedError` — a valid red.
